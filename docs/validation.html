Validation Rules

GherkinLang validates generated code to ensure functional purity and best practices.

Overview

Validation runs automatically after code generation and checks for:

  • Syntax - Valid JavaScript syntax
  • Purity - Functional programming principles
  • Lint - ESLint code quality rules

Configure validation in .gherkinrc.json:

{
  "validation": {
    "syntax": true,
    "purity": true,
    "lint": true
  }
}

Allowed Patterns

Pure Functions

// ✅ Pure function - same input always gives same output
const add = (a, b) => a + b;

// ✅ Higher-order function
const map = (arr, fn) => arr.map(fn);

// ✅ Recursion instead of loops
const factorial = (n) => n <= 1 ? 1 : n * factorial(n - 1);

Immutable Operations

// ✅ Spread operator for new objects
const updateUser = (user, updates) => ({ ...user, ...updates });

// ✅ Array spread for new arrays
const append = (arr, item) => [...arr, item];

// ✅ Filter creates new array
const removeById = (arr, id) => arr.filter(x => x.id !== id);

Allowed Globals

Pattern Notes
console.log, console.* Logging is allowed
new Date(), Date.now() Date operations are allowed
Math.floor, Math.ceil, etc. Deterministic Math methods allowed
JSON.parse, JSON.stringify JSON operations allowed
Object.keys, Object.values Non-mutating Object methods
Array.isArray Type checking allowed

Forbidden Patterns

Imperative Loops

// ❌ for loop - use map/filter/reduce instead
for (let i = 0; i < arr.length; i++) { }

// ❌ while loop - use recursion instead
while (condition) { }

// ❌ for...of - use array methods instead
for (const item of items) { }

Mutations

// ❌ Push mutates the array
arr.push(item);

// ❌ Sort mutates in place
arr.sort();

// ❌ Direct property mutation
obj.prop = value;

Side Effects

// ❌ File system operations
fs.readFileSync('file.txt');

// ❌ Network requests
fetch('https://api.example.com');

// ❌ Timers
setTimeout(() => {}, 1000);

Non-Deterministic

// ❌ Random numbers are non-deterministic
Math.random();

Browser Globals

// ❌ DOM manipulation
document.getElementById('app');

// ❌ Browser storage
localStorage.setItem('key', 'value');

// ❌ Window object
window.location.href;

Classes (Regular)

// ❌ Regular class declarations
class MyClass {
  method() { }
}

State Manager Exception

Classes that follow the state manager pattern are allowed:

// ✅ State manager class with reduce + send methods
class CounterService {
  constructor() {
    this.state = { count: 0 };
  }

  // Pure reducer function
  reduce(state, message) {
    switch (message.type) {
      case 'increment':
        return { ...state, count: state.count + 1 };
      default:
        return state;
    }
  }

  // Dispatch method
  send(message) {
    this.state = this.reduce(this.state, message);
    return this.state;
  }
}

Requirements for state manager classes:

  • Must have a reduce(state, message) method
  • Must have a send(message) method
  • Reducer must be pure (return new state, not mutate)

Common Validation Errors

Mutation Error

Error: 'push' mutates the array.
Use immutable alternatives like spread with slice.

Fix: Use [...arr, item] instead of arr.push(item)

Forbidden Construct

Error: ForStatement is forbidden.
Use functional alternatives like map, filter, or reduce.

Fix: Replace for loop with map, filter, or reduce

Side Effect

Error: 'fs.readFile' performs file I/O.
Pure functions should not access the file system.

Fix: Pass file contents as a parameter instead of reading inside the function

Global Access

Error: 'window' is a global object.
Avoid accessing global state.

Fix: Pass required values as function parameters

Tip: Use --verbose flag to see detailed validation errors with code snippets.
