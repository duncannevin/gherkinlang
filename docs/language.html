Language Guide

GherkinLang extends standard Gherkin syntax with features for code generation.

Overview

GherkinLang files use the .feature extension and contain:

  • Feature - The module being defined
  • Background - Shared setup including imports and state
  • Scenarios - Individual functions or behaviors

Features

Every file starts with a Feature declaration:

Feature: Calculator
  A simple calculator for mathematical operations.
  Provides pure functions for arithmetic.

The feature name becomes the module name. Lines after the feature name are treated as documentation.

Naming: Feature names should use PascalCase without spaces (e.g., UserService, DatabaseService).

Scenarios

Scenarios define individual functions or behaviors:

Scenario: Add two numbers
  Given two numbers a and b
  When I add them together
  Then the result is a + b

Scenario Keywords

Keyword Purpose
Given Define inputs, preconditions, parameters
When Describe the action or transformation
Then Specify the expected output or result
And Continue any of the above

Explicit Function Definition

For clearer function signatures, use the explicit pattern:

Scenario: createUser defines a function
  Given function createUser accepts name, email, and password
  When I validate the input
  And I hash the password
  Then return the new user object

Background

The Background section defines shared setup for all scenarios:

Background:
  Given import lodash as _
  And import date-fns as dateFns

Imports

Import other features or external libraries in the Background:

Background:
  # Import another feature
  Given import DatabaseService as db
  
  # Import external npm package
  And import lodash as _
  And import date-fns as dateFns

Imported features are resolved from the same project. External packages must be installed via npm.

State Management

GherkinLang supports stateful services using a pure reducer pattern:

Feature: CounterService
  A simple counter with increment/decrement operations.

Background:
  Given initial state is { count: 0 }
  And state accepts messages:
    | increment | add 1 to count    |
    | decrement | subtract 1        |
    | reset     | set count to 0    |

Scenario: increment defines a message handler
  Given state contains count
  When receive increment message
  Then return new state with count + 1

Scenario: getCount queries state
  When I query the current count
  Then return the count value

Generated JavaScript

State management generates a class with a pure reducer:

class CounterService {
  constructor() {
    this.state = { count: 0 };
  }

  reduce(state, message) {
    switch (message.type) {
      case 'increment':
        return { ...state, count: state.count + 1 };
      case 'decrement':
        return { ...state, count: state.count - 1 };
      case 'reset':
        return { ...state, count: 0 };
      default:
        return state;
    }
  }

  send(message) {
    this.state = this.reduce(this.state, message);
    return this.state;
  }

  getCount() {
    return this.state.count;
  }
}

Collections

Describe collection operations naturally:

Scenario: Filter active users
  Given an array of users
  When I filter by active status
  Then only users with active = true are returned

Scenario: Get user names
  Given an array of users
  When I extract all names
  Then an array of name strings is returned

Scenario: Calculate total price
  Given an array of items with prices
  When I sum all prices
  Then the total price is returned

These generate idiomatic functional code using filter, map, reduce.

Common Patterns

Validation

Scenario: Validate email format
  Given an email string
  When I validate the email format
  Then return true if valid, false otherwise

Transformation

Scenario: Capitalize words
  Given a string of words
  When I capitalize each word
  Then each word starts with uppercase

Conditional Logic

Scenario: Process payment
  Given a payment amount and user balance
  When the balance is sufficient
  Then deduct the amount and return success
  Otherwise
  Then return insufficient funds error

Error Handling

Scenario: Safe divide
  Given a dividend and divisor
  When divisor is zero
  Then return null or error result
  Otherwise
  Then return the quotient
Best Practice: Write scenarios that describe what should happen, not how. Let the AI determine the implementation details.
